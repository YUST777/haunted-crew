# Repository structure

```text
.kiro/            specs, steering and hooks for building this repo with Kiro (see .kiro/README.md)
bridge/           Node bridge: hook events, ACP agents, workflows, merges, dashboard, MCP crew server
  bin/            launcher (haunted-crew.mjs), install-hooks, send-event, crew-mcp, demo-agent, install-minecraft
  src/            one module per concern (acp, agents, normalize, state, workflows, worktrees, tools, ...)
  test/           node:test files, one per module, plus scripted fake agents
mod/              Fabric mod
  src/main/java/dev/hauntedcrew/          server + shared: BridgeClient, CrewManager, GhostEntity, Office, ...
  src/client/java/dev/hauntedcrew/client/ screens and rendering: ConsoleScreen, WorkflowScreen, GhostModel, ...
  src/main/resources/assets/hauntedcrew/  models, textures, lang, tour media (some generated by tools/)
docs/             user and reference docs; the website renders these at /docs, so they are the single source
landing_page/
  site/           the website (Vite + TanStack Router)
  *.png           design renders; the huge upscales are gitignored
tools/
  ghost/          Blender ghost model -> mod model JSON + texture (blender_export.py, paint_ghost.py)
  monitor/ office/ board/   monitor model, office and mansion builders, board assets
  hero/           website hero and chase assets; bmcp.py talks to the MCP for Blender socket
  kiro/           scripts the Kiro hooks call: check.sh, guard-shell.mjs
skills/           haunted-crew-setup/SKILL.md, the setup skill shipped as a Kiro Power
INSTALL_PROMPT.md paste-in install prompt; the website's "Copy install prompt" button copies its text block
plugin.json       Kiro Power / agent plugin manifest
```

## Where things go

- A new bridge concern gets its own `src/<name>.mjs` and `test/<name>.test.mjs`.
- Files a tool generates (model JSON, textures, GLB, webp) are committed, and the script that made them sits in
  `tools/` with a header comment saying how to rerun it.
- Runtime state of a user's project lives in `<project>/.haunted-crew/`, never in this repo.
- Do not add files under `.kiro/agents/` or `.kiro/hooks/haunted-crew.json` by hand: the launcher writes those into
  the user's project. The `haunted-crew-*.json` hooks in this repo are for dogfooding this repo only.
